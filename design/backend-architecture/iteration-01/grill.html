Security Grilling

G-001 — Wallet header auth = full user impersonation CRITICAL

x-wallet-address header auth allows any client to impersonate any user. No signature, no token, no session.

Attack: curl -H "x-wallet-address: victim_wallet" https://api/contacts returns victim's data.

Public Vercel deployment + zero auth = open data access for all users.

G-002 — CSRF with header-based auth MINOR

Custom headers cannot be set by cross-origin form submissions. CORS + custom header = adequate. Not a real risk. Needs documentation only.

G-003 — IP rate limiting blocks shared networks MAJOR

100 req/min per IP. Users behind NAT/VPN share IPs. One heavy user blocks others. Fix: per-user rate limiting for authenticated endpoints.

G-004 — Pi wallet address format unvalidated MAJOR

Frontend uses Ethereum-style 0x.... Pi Network uses Stellar addresses (G..., 56 chars). No validation on backend. Will break in Phase 4.

G-005 — No XSS sanitization on text fields MAJOR

Zod validates length but doesn't strip HTML. Stored XSS risk. Fix: use xss npm package in Zod transforms.

Concurrency Grilling

G-006 — Simultaneous Pi payments between same users CRITICAL

User A sends 100π to B while B sends 50π to A. Both create pending transactions. Proposal says "single DB operation" but Pi payments are multi-step. Contradiction.

These are independent blockchain transactions. Each must complete/fail independently. Risk is pending state lingering (see G-023).

G-007 — Summary aggregation race MINOR

Single-query aggregation with READ COMMITTED is fine at expected volume. Non-issue.

G-008 — Contact delete during tx creation MINOR

FK defaults to RESTRICT. Need to decide: SetNull, Cascade, or Restrict.

Data Integrity

G-009 — Float for financial amounts CRITICAL

IEEE 754: 0.1 + 0.2 = 0.30000000000000004. After thousands of transactions, balance drifts.

Fix: Decimal @db.Decimal(18,7) in Prisma.

G-010 — Contact totals undefined MAJOR

Frontend expects totalCredit/totalDebit. Backend doesn't store. Needs JOIN+GROUP BY.

G-011 — Deleting blockchain tx MAJOR

Soft-delete + block pi_network deletion.

G-012 — No audit trail MAJOR

Hard deletes lose data. Need soft-delete (deletedAt).

Failure & Deployment

G-013 — Pool exhaustion MAJOR

Need explicit connection_limit and pool_timeout.

G-014 — No graceful shutdown MINOR

Implement SIGTERM handler.

G-015 — No DB retry MINOR

Acceptable for Phase 1-3.

G-016 — Amount boundaries MINOR

Min 0.0000001, max 1M.

G-017 — Name uniqueness MINOR

Names not unique by design. Use IDs.

G-018 — Idempotency key optional CRITICAL

Must be REQUIRED on POST /api/transactions.

G-019 — Contact idempotency MINOR

Natural via unique constraint. Handle P2002 gracefully.

G-020 — Key expiry MINOR

Non-issue. Keys are tx columns.

G-021 — Migration failure MAJOR

Railway blue-green keeps old container. Always backward-compatible migrations.

G-022 — No staging MAJOR

Acceptable for small team.

G-023 — Pending tx stuck forever CRITICAL

30-min TTL + reconciliation cron job.

G-024 — Payment completion double-call MAJOR

Check status before processing. Idempotent.

G-025 — N+1 contacts query MAJOR

Single JOIN+GROUP BY raw SQL.

G-026 — No contactId ownership check MAJOR

Verify contactId belongs to req.user.id.

G-027 — Name-keyed pending tx MINOR

Frontend refactor Phase 2.

G-028 — Contact.txHash mismatch MINOR

Frontend type update Phase 2.
